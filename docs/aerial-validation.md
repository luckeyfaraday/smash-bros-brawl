# Mario neutral aerial validation

Build `brawl-lab-003` enables AttackAirN and its LandingAirN animation, alongside
the three-hit jab. Its main script and both CHR0 clips come from the local USA
Rev 1 PACs. Exact input processing, physics, collision update order and landing
animation rate still need comparison with the original game in Dolphin.

## Extracted behavior

Times below are zero-based script/animation times, not elapsed video frames.
Hitlag freezes animation time while simulation ticks continue.

| Animation time | Script operation |
| --- | --- |
| 0–1 | No hitboxes; aerial landing-lag flag off |
| 2 | Set RA-Bit[30]; create two 10% hitboxes with radius 4 |
| 5 | Replace both with 5% hitboxes of radius 3; hitbox 0 also changes bone |
| 29 | Clear both hitboxes |
| 33 | Clear RA-Bit[30] |

RA-Bit[30] (`0x2200001e`) is named `EnableLandingLag` in
[brawllib_rs's variable definitions](https://github.com/rukai/brawllib_rs/blob/master/src/script_ast/variable_ast.rs).
The original AttackAirN clip has 46 samples and LandingAirN has 31.
`FitMario.pac` attribute `0x140`, labeled `Nair Landing Lag?` by the existing
OpenSA3 reference table, contains 10; normal landing lag at `0x13c` contains 3.

The runtime executes the raw commands. Early and late hitboxes belong to the
same attack: replacing them does not reset the once-per-target hit restriction.
The result is 10% for an early contact or 5% for a first late contact, never 15%
from hitting with both phases of one aerial.

## Current integration rules

- A fresh attack press while airborne starts neutral aerial at time 0. Jump
  startup does not buffer an attack press; jump first, then attack.
- Drift and fast fall remain available. Jump/attack presses during the move do
  not cancel it or consume the remaining air jump. Its 46-sample clip ending
  returns Mario to the falling state unless he has already landed.
- The current aerial frame's script executes before floor contact is resolved.
  Landing at times 2–32 selects LandingAirN and ten ticks of recovery. Landing
  at times 0–1 or 33 onward uses the normal three-tick recovery.
- Landing clears the move VM and all hitboxes before fighter hit detection, so
  no aerial hit remains active on the ground. Respawn also clears the move.
- During the ten-tick aerial landing, the renderer samples the original landing
  clip at `floor(age * 30 / 9)`: the first pose at age 0, the last at age 9.
  Actions unlock at age 10. This scaling is a prototype choice pending engine
  comparison. Normal landing still uses the existing Wait1 pose.
- An unsupported script command remains visible as an error even if the same
  tick would have landed and discarded the VM. The browser pauses on that error.

These rules describe this browser implementation. They do not establish
frame-accurate Brawl input buffering, auto-cancel ordering, animation rates or
knockback. The existing provisional hit response is unchanged.

## Regression recording

`tests/fixtures/mario-neutral-aerial.json` is a 90-tick browser recording with
per-frame hashes. It walks right for ten ticks, taps jump on tick 11, attacks on
tick 17, and taps down while descending on tick 43.

| Simulation tick | Expected event |
| --- | --- |
| 16 | Short hop leaves the platform |
| 17 | AttackAirN begins at animation time 0 |
| 19 | Early contact adds 10%; hitlag begins |
| 28 | Late hitboxes replace early ones; damage remains 10% |
| 43 | Fast fall begins while AttackAirN continues |
| 51 | LandingAirN begins; all attack hitboxes are cleared |
| 61 | Landing recovery ends |

The recording was generated by this simulation, not Dolphin. `npm test` checks
its hashes along with the existing jab recording. Separate tests exercise late
first contact, both landing-flag boundaries, recovery locks, air-jump access,
hitbox cleanup, faults, and original pose data.

Browser tests perform the short-hop/attack/fast-fall sequence through actual
keyboard controls, check both damage phases and landing recovery, inspect the
desktop and phone timelines, and replay an exported recording containing both
the jab chain and neutral aerial in Node.

```powershell
npm run trace:replay -- tests/fixtures/mario-neutral-aerial.json artifacts/aerial-trace.json
```

Use a fresh output filename. Keep future Dolphin measurements separate from
these browser traces, with the disc revision, emulator version and starting
state recorded. Priority comparisons are landing exactly as RA-Bit[30] changes,
input during jump startup/recovery, and landing animation progression.
